# Функціональні тести сайту

Автоматичний браузер (Chromium через Playwright) відкриває сайт так, як його
відкриває читач, і перевіряє, що все на місці. Кожна сторінка – у двох
ширинах: телефон (390 px) і ноутбук (1366 px).

## Що перевіряється

| Файл | Що саме |
| --- | --- |
| `pages.spec.ts` | Кожен тип сторінки обома мовами: головна, бібліотека, мапа, «Про проєкт», команда, політика, умови, **кожне рішення** з `src/content/summaries` і вибірка сторінок справ без огляду (по одній на суд). Сторінка відповідає 200, має рівно один `<h1>`, у консолі браузера немає помилок, сторінка не ширша за екран. Справа без огляду – темна сторінка «ще досліджуємо». На ширині ноутбука ще й SEO: `<title>`, canonical, hreflang uk/en/x-default, довжина опису (не довше 160 знаків, а в рішень – не коротше 110, як у `src/lib/seo.ts`), JSON-LD рішень (`Article` + `BreadcrumbList`). |
| `header.spec.ts` | Пункти меню ведуть на живі сторінки; на телефоні «бургер» відкриває і закриває меню, Esc теж закриває; перемикач UA/EN веде на ту саму сторінку іншою мовою. |
| `registry.spec.ts` | Бібліотека: фільтр за судом звужує список, число над списком збігається з рядками, «Скинути» повертає все; посилання `?material=lit` показує саме рішення з оглядами; пошук знаходить справу за назвою, а безнадійний запит пропонує скинути. |
| `decision.spec.ts` | Сторінка рішення: зміст «На цій сторінці» веде на справжні розділи, хронологія є, «Читати рішення» має посилання й відкривається в новій вкладці. |
| `site.spec.ts` | Мапа намальована; неіснуюча адреса (`/uk/nope`) показує сторінку 404; блогу немає, доки немає дописів (ні сторінки, ні пункту «Блог»). |
| `http.spec.ts` | **Лише живий сайт:** `/` перенаправляє за мовою браузера (307); `robots.txt` не пускає в адмінку й блокує CCBot; `sitemap.xml` читається, і сайт або повністю відкритий для пошуковиків, або повністю закритий; `security.txt` не прострочений; `favicon.ico`; заголовки безпеки; сторінка входу в адмінку має `noindex` і підказки для редактора (`/admin-guide.js`); пошук адмінки без входу – 404; `/health` не називає версію. |

Список рішень і справ тести беруть із тих самих файлів, що й збірка
(`tests/e2e/routes.ts`), тож нове рішення потрапляє в перевірку саме.

## Як запустити

Один раз після `npm ci` потрібен браузер: `npx playwright install chromium`.

```sh
npm run test:e2e         # збирає сайт із файлів (npx astro build) і перевіряє збірку
npm run test:e2e:live    # перевіряє живий сайт https://nasvitlo.ucu.edu.ua
```

Інша адреса – змінною `BASE_URL`:

```sh
BASE_URL=https://staging.example.org npx playwright test
```

Повторити перевірку без нової збірки – `npx playwright test`. Лише один файл
чи одна ширина – `npx playwright test registry --project=mobile`.

Перевірки з `http.spec.ts` на локальній збірці пропускаються з поясненням:
редирект `/`, адмінку й заголовки робить Worker Cloudflare, а локальний
сервер (`serve.mjs`) лише віддає файли з `dist/client`.

Щоночі те саме проходить GitHub Actions (`.github/workflows/e2e-live.yml`);
запустити вручну – Actions → e2e-live → Run workflow. PR він не блокує.

## Як читати провал

Кожен тест названий за тим, що він перевіряє, наприклад
`[mobile] › registry.spec.ts › a court filter narrows the list…` – отже, на
телефоні зламався фільтр бібліотеки. Під назвою – що очікувалось і що
вийшло:

- `HTTP status … Expected: 200, Received: 404` – сторінки немає;
- `browser console errors … console: …` – сторінка кинула помилку в консоль,
  з адресою файлу;
- `document wider than the window: div.x → 512px` – на цій ширині щось
  вилазить за екран, і названо, що саме;
- `meta description «…» Expected: <= 160` – опис для пошуковика задовгий.

Повний звіт зі знімком екрана й записом кожного кроку:

```sh
npx playwright show-report
```

У GitHub Actions той самий звіт лежить в артефакті `playwright-report`
запуску.

**Відомі вади.** Якщо вада знайдена, але ще не виправлена, її сторінка
записана в `KNOWN_DEFECTS` у `pages.spec.ts`: тест позначений як «очікувано
падає» і не зупиняє запуск. Коли ваду виправлять, тест почне проходити – і
саме тому впаде з вимогою прибрати рядок із `KNOWN_DEFECTS`. Зараз там одна:
англійський опис сторінки мапи – 178 знаків замість 160.

На живому сайті кожен тест, що впав, повторюється один раз: якщо з другої
спроби пройшов, звіт позначає його як `flaky` – найчастіше це мережа, а не
сайт.
